# 评测工作台：业界基础功能与建设范围

调研日期：2026-10-28。本文记录官方产品事实和功能取舍；具体接口、数据格式及运行方式以[项目评测文档](../../website-docs/03-features/15-evaluation.md)和源码为准。

## 官方产品事实

| 系统 | 已核实的基础能力 | 官方依据 |
| --- | --- | --- |
| Langfuse | 实验列表与对比、逐题输出和评分、成本与延迟、阈值筛选、逐题执行记录、人工评分和标注队列。公平比较要求相同数据集版本和评分器定义，并记录应用、模型或提示词版本。 | [实验对比](https://langfuse.com/docs/evaluation/experiments/compare-experiments)、[标注队列](https://langfuse.com/docs/evaluation/evaluation-methods/annotation-queues) |
| LangSmith | 题目增删改产生数据集版本，历史版本只读；支持版本标签、分组、筛选及 CSV/JSONL 导出。实验可并排比较答案、分数、文本差异和执行记录，并筛选改善或退化的题目。 | [数据集管理](https://docs.langchain.com/langsmith/manage-datasets)、[实验比较](https://docs.langchain.com/langsmith/compare-experiment-results) |
| Phoenix | 版本化数据集、响应和检索评测、实验记录、Tracing、提示词版本管理和调用重放。 | [官方功能说明](https://github.com/Arize-ai/phoenix/blob/main/README.md) |
| Braintrust | 实验历史展示平均分、错误数、耗时、Token 和成本；支持逐题结果、输入输出搜索、分数区间筛选、按耗时或 Token 排序、按元数据分组，以及实验差异对比。 | [结果分析](https://www.braintrust.dev/foundations/how-to-analyze-your-eval-results)、[实验比较](https://www.braintrust.dev/foundations/comparing-experiments) |

这些产品共同采用“数据集 → 实验运行 → 逐题结果 → 执行记录 → 评分和复核 → 历史比较”的工作流。工作台应同时回答“整体效果如何”和“这一题为什么失败”。

## 本地评测引擎的接入边界

以下是建设工作台时需要处理的引擎约束，不能仅靠前端展示解决：

- 内置样例来自本地 Parquet 文件；自建数据集通过工作台导入或编辑，保存为数据库草稿和不可变发布版本。数据源与字段定义见[数据集服务](../../internal/application/service/dataset.go)。
- 评测流程需要保留任务历史、当次题目和答案快照、逐题输出及指标，不能只保存汇总分；服务重启后的查询和运行中断状态也需要有明确语义。执行入口见[评测服务](../../internal/application/service/evaluation.go)。
- 现有指标以检索指标和 BLEU/ROUGE 为主，不能直接宣称已经衡量语义正确性、忠实度或拒答正确性。指标定义见[评测类型](../../internal/types/evaluation.go)和[指标钩子](../../internal/application/service/metric_hook.go)。
- 语料导入范围及检索结果到证据段落的映射会影响评分口径。工作台需要明确实验评测语料的范围，不能把局部语料结果直接解释成真实全库检索表现。见[语料装配](../../internal/application/service/evaluation.go)和[检索评分输入](../../internal/application/service/metric_hook.go)。

## 此次基础范围

以下为本项目的建设建议，不代表所有业界系统必须以相同方式实现：

1. **数据集维护**：新建及 JSON/JSONL/CSV 导入；编辑问题、参考答案、共享证据；保存不完整草稿，严格校验后发布版本，查看或恢复旧版；保留完整语料。
2. **发起评测**：选择现有数据集、参考知识库和模型，保存当次运行配置及数据集快照。
3. **评测历史**：运行时间、状态、进度、成功和失败题数、汇总指标；历史记录可在服务重启后查询。
4. **逐题详情**：问题、参考答案、最终答案、状态、耗时、错误和各项评测指标。
5. **执行过程**：按实际执行的节点展示输入、输出、状态和耗时；检索与重排结果能够查看证据内容、来源及原始排序分。
6. **结果复核**：搜索题目，按失败或低分筛选，导出本次运行结果，便于人工分析。
7. **运行对比**：相同数据集与指标版本的成功运行可对比汇总分数和逐题最终答案。

页面可以组织为“数据集 / 评测历史”，从历史进入运行概览和题目列表，再进入单题执行详情。该结构先满足浏览、执行和定位问题的完整链路。

## 后续功能排序

| 优先级 | 功能 | 目的 |
| --- | --- | --- |
| 紧接基础范围 | 多运行对比、逐题改善/退化筛选和分组统计 | 扩展已有两次运行对比，定位特定场景的变化 |
| 紧接基础范围 | 题目标签、分组汇总及批量编辑 | 在已有数据集维护和版本发布基础上定位特定场景短板 |
| 紧接基础范围 | 人工通过/不通过、评分、评语、错误分类、修正答案 | 复核自动指标，沉淀可执行的质量标准 |
| 后续扩展 | 失败题或选定题重跑、取消运行、并发控制 | 改善评测执行效率，保留原始运行证据 |
| 后续扩展 | 可配置评分器、语义正确性、忠实度、引用与拒答评分 | 补足文字重合指标的能力边界 |
| 后续扩展 | 重复运行统计、Token 与成本、阈值门槛和持续集成 | 量化稳定性、成本和回归风险 |
| 后续扩展 | 从真实对话添加评测题、共享标注队列和线上抽样评分 | 将生产问题转成可重复验证的案例 |

## 评分与历史的基本约束

- **排序分与评测分分开**：检索相似度、重排分是排序信号；Recall、NDCG、BLEU 等是质量指标。没有评分器的节点显示“未评分/不适用”，不虚构节点正确率。
- **执行失败与低分分开**：应用调用失败、评分器失败、题目低分是不同结果；汇总需显示有效样本数。Langfuse 明确要求先处理评分器失败或缺失结果，再完成比较。见[实验比较中的错误处理](https://langfuse.com/docs/evaluation/experiments/compare-experiments)。
- **历史可解释**：旧运行展示当时的输入、参考答案和配置；重跑建立新运行或新尝试，不覆盖旧证据。
- **比较条件明确**：数据集或指标定义变化时，不能只凭平均分宣称改善。见[Langfuse 的比较条件](https://langfuse.com/docs/evaluation/experiments/compare-experiments)。
- **只展示实际记录**：流程表示系统执行操作及其输入输出，不依赖模型内部思维过程；未采集的耗时、Token 或成本不填造估计值。
- **沿用权限边界**：执行权限与读取权限区分；历史、题目详情及导出都按当前工作空间隔离，配置快照不包含模型凭证。现有路由策略见[评测路由](../../internal/router/routes_infra.go)。
